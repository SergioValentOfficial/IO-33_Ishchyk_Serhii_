PRD Heliostat

Геліостат — двовісна платформа, що орієнтується за освітленістю.

Для кого: навчальний макет для студентів і розробників вбудованих систем. Проєкт має сенс як практична модель автоматичного орієнтування платформи за даними датчиків освітленості.

Проблема:

Потрібно автоматично визначати напрямок, у якому освітлення сильніше, і коригувати орієнтацію макета сонячної панелі.

Рішення:

Чотири LDR утворюють квадрант. STM32F411RE читає їх через ADC та визначає напрямок корекції. Два SG92R змінюють азимут і елевацію. W25Q64 використовується для зберігання журналу та параметрів. UART використовується для CLI калібрування.

Склад системи

| Компонент | К-сть | Інтерфейс | Роль |
| --- | --- | --- | --- |
| NUCLEO-F411RE | 1 | — | Контролер |
| GM5528 | 4 | ADC | Сенсори освітленості |
| SG92R | 2 | PWM | Виконавчі механізми |
| W25Q64 | 1 | SPI | Пам'ять |
| FT232RL | 1 | UART | CLI |
| LED | 2 | GPIO | Індикація |

Вибір ключових компонентів:

| Компонент | Пов’язані FR | Альтернатива | Чому не обрана |
| --- | --- | --- | --- |
| GM5528 | FR-01, FR-02, FR-03 | BH1750 | 4 LDR простіші для квадрантного порівняння через ADC. |
| SG92R | FR-04, FR-05, FR-06 | MG90S | SG92R достатній для макета і вказаний у темі. |
| W25Q64 | FR-07, FR-10 | Внутрішня Flash STM32 | За темою потрібна окрема SPI Flash для журналу і параметрів. |

Функціональні вимоги:

| ID | Вимога |
| --- | --- |
| FR-01 | Система повинна ініціалізувати ADC та отримувати значення з чотирьох LDR. |
| FR-02 | Система повинна порівнювати рівні освітленості чотирьох квадрантів. |
| FR-03 | Система повинна визначати напрямок корекції по двох осях. |
| FR-04 | Система повинна формувати PWM для двох сервоприводів. |
| FR-05 | Система повинна обмежувати положення сервоприводів заданими межами. |
| FR-06 | Система повинна переходити у задане паркове положення за умов нічного режиму. |
| FR-07 | Система повинна мати можливість зберігати журнал/параметри у W25Q64. |
| FR-08 | Система повинна мати UART CLI для калібрування та діагностики. |
| FR-09 | Система повинна індикувати поточний режим. |
| FR-10 | Після перезапуску система повинна використовувати збережені параметри калібрування, якщо вони записані. |

Нефункціональні вимоги:

Прошивка повинна працювати на STM32F411RE.

Периферія повинна бути налаштована через STM32CubeMX/HAL.

Проєкт повинен збиратися наявним Makefile та arm-none-eabi toolchain.

На Кроці 6 реалізується лише ініціалізація інтерфейсів; драйвери сенсорів/Flash не є частиною Кроку 6.

Параметри, що потребують калібрування, мають бути змінними.

Критерії приймання:

| ID / FR | Перевірка | Очікуваний результат |
| --- | --- | --- |
| AT-01 | Запуск firmware | Система стартує без помилки. |
| AT-02 / FR-01 | 4 ADC | Усі чотири канали доступні. |
| AT-03 / FR-01, FR-02 | Змінити освітлення одного квадранта | Відповідний ADC змінюється. |
| AT-04 / FR-04, FR-05 | PWM | Обидва канали генерують PWM. |
| AT-05 / FR-07, FR-10 | SPI | SPI успішно ініціалізується. |
| AT-06 / FR-08 | UART | CLI/діагностика доступні. |
| AT-07 / FR-02, FR-03 | Корекція | Зміна показань LDR змінює розраховану корекцію. |
| AT-08 / FR-06 | Нічний режим | За заданої умови формується команда парковки. |
